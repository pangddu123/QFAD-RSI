# QFAD writer 的检索轨迹反馈

入口是 `experiments/qwen27b_rsi/run_targeted_writer.py`。同一个抽取策略按原文到达顺序建图。每个训练窗口从同一患者图分出 G 条同策略轨迹。默认大样本清单取 G=8。后续每轮读取本分支上一轮生成的图，直到窗口结束才进行一次参数更新。部署时 writer 只接收原文及此前已写入的事实。每条事实和关系保留 `source_id`、零基行号和逐字引用。

## 医学文字反馈

数据依据是 [患者 1、2 的任务分布和状态更新原题](dataset_profile.json)。抽取所需的区别取决于这条原文所描述的事件。下表说明如何从原文和检索结果生成提示。英文提示适配当前英文 MedMemoryBench。

| 医学区别 | 触发依据 | 提示 writer 重新核对的内容 |
|---|---|---|
| 用药建议、执行、停用 | 查询要求实际用药状态，交付的窗口只有医嘱，患者确认行位于本次输入 | 指向确认行，分开记录建议者、执行者和状态 |
| 记录时间和事件时间 | 缺少带日期的记录，或来源核验发现模型把相对时间写成具体日期 | 保存原始时间精度，将事件时间与记录日期分别索引 |
| 测量和趋势 | 检索缺少要求的观测窗口，或同名指标只交付一个时点 | 保留单位、测量条件及对应时间，每个可比较的读数都可回到来源 |
| 临床约束、断言和监测 | 来源核验发现混淆患者与亲属、把未测写成正常，或把监测要求写成已出现异常 | 保留主体、报告者、确定性和监测条件 |
| 多阶段变化 | 某次干预或响应的证据没有进入原文窗口 | 保留前后状态与响应持续时间，以原文支持的关系连接事件 |

提示分成三处。抽取提示在部署时也生效，要求 writer 提取“谁在什么时候报告了什么”，并保留原文行号。来源裁判按字段核验事实和关系，给出错误类别和依据。训练教师再接收针对本轮的文字修正，每轮至多三条。教师不接收参考答案或整份标注。小样本联调课程（prepare --smoke）有四个训练块和七道来源锚定问题。患者 1 的三次写入包括旧记录及同一指标的复查记录。患者 2 保留单次写入。可通过训练清单的 `turns_per_rollout` 调整窗口长度。

## 多轮归因

先在终态图回答固定问题。对于终态仍缺失的证据条件，在相同问题、可见截止点和上下文预算下重放初始图及每轮写入后的图。

- 若证据从未覆盖且原始写入就漏掉了已核验的行，将来源定位提示发给原文所属轮次。
- 若曾覆盖，定位最后一次由覆盖变为缺失的写入。只有之前支撑该条件的来源被移出，或其窗口确实丢了原文锚点，才将回归提示发给这次写入。恢复的缺失不再产生终态惩罚。
- 若证据已交付、因上下文上限跳过，或只有评分变化而没有对应的证据变化，跳过该条查询提示。各轮的格式和来源核验错误分别归给各自的写入。

每条 `*_b*.credit.json` 记录患者、策略步数、采样动作、原文所属轮次、查询、前缀检索结果及每轮的提示。已满足的终态查询省去中间重放。归因覆盖同一策略版本的窗口，窗口外已冻结的历史写入不参与本次蒸馏。前缀比较衡量一次写入对当时检索结果的边际影响；多个写入交互时，该规则不提供唯一的因果分解。

例如对“初检 HbA1c 是多少”和“本次复查是多少”，同一复查记录可以同时引用两个值。初检提示要求核对原始检查时间；复查提示要求明确哪个是比较值、哪个是新值。对于“很少头晕”，来源核验提示要求保留程度和频率。对于“复查电解质”，提示要求独立索引监测计划，只有原文出现化验结果才索引观测值。

已对手写虚构指标 X 用冻结的 Qwen FP8 做过三组贪心推理。预先计算的数值与行号配对分别是无提示 0/2、仅行号 2/2、行号加医学提示 2/2。回看原始输出，仅最后一组另写出了两次测量的进食条件。这是事后观察。该探针使用预设的定位提示，衡量提示改变抽取的方式，不能测量训练增益或替代基准查询评估。可用 `probe_clinical_prompt.py --out 新目录` 复跑。

## 参数更新与对照

标量奖励包含有充分证据的答对题数、终态证据覆盖率和各轮来源错误比例的均值。组内相对优势更新整条轨迹。只有收到提示的动作才计算学生相对同权重、停止梯度教师的全词表反向 KL。分母包含整条轨迹的输出 token 数和组大小。默认权重 0.1 是初始设置。[Frans 等，§4](https://arxiv.org/pdf/2611.05266)

三个 writer 条件为冻结、仅标量 RL、标量 RL 加文字反馈。同组对照从相同基座开始，使用相同来源清单、解码、检索、回答和评分协议。相同回答提示复用冻结组的回答。保存逐题胜负、正确数，以及相对冻结组、标量组和 RAW-RAG 的结果。

## 运行入口

在 QFAD-RSI 根目录使用现有 MedMemoryBench 环境。`prepare` 仅在本地生成清单。输出目录须为新目录。默认使用已有索引和 RAW-RAG 结果的十位患者，患者 5–10 用于训练、1–2 用于验证、3–4 用于最终比较；后两组在此前项目中已有实验记录。

```bash
../MedMemoryBench/.venv/bin/python experiments/qwen27b_rsi/run_targeted_writer.py prepare --group-size 8 --out results/targeted_writer_run
```

训练池的 581 道原题有 482 道能把所有关键点关联到当时可见的有索引非噪声会话。其余 99 道整题排除。每个关键点在标注会话内选择词项重叠最多的原文块供模型写入；相同问题在不同写入中的引用按患者和题号去重统计。同一窗口同一道问题只评分一次。关键点描述用于覆盖裁判。只有逐字出现在原文的完整描述才提供行锚点，其余保留会话级来源，可利用覆盖回退和逐事实来源核验归因。当前清单的 2,210 个问题－条件中只有 1 个能通过整段逐字匹配；强行把候选行当成金标会夸大反馈精度。Writer 观察只含原文及已写入事实。

该版本生成 1,113 次顺序写入、2,017 个查询－写入关联、381 个窗口。每个策略组 G=8 对应每个训练条件计划 3,048 条轨迹、8,904 个生成动作，最多 381 次更新机会。G 可在 prepare 时修改，例如 G=16 对应 6,096 条轨迹。首轮按每批至多 4 条分开生成，后续每条轨迹使用自己的历史；所有批次共享旧策略，整组一起算相对优势并进入同一次更新判断。扩大 G 不增加独立问题数。等回报组的标量优势全零，文字反馈组还可由非零权重的归因提示触发更新。每个窗口在 `*.rewards.json` 记录实际轨迹数、不同输出序列数、回报、优势与更新信息。训练清单的数量只表示预算，结果应以实际完成的轨迹、梯度更新和同题评测为准。

`pilot` 使用该清单在已配置的 2A100 项目目录部署对应版本的 worker，训练两个策略并评估三个条件。运行前需要既有的 embedding、rerank、回答服务与本地评分环境可用，GPU 1 需有足够显存。默认验证集覆盖患者 1、2 全部检查点，共 3,594 个原文块、197 道题。旧版四写入、七训练题、十四验证题的联调协议可通过 `prepare --smoke` 选择，或继续使用已经生成的清单。

```bash
../MedMemoryBench/.venv/bin/python experiments/qwen27b_rsi/run_targeted_writer.py pilot --out results/targeted_writer_run
```

若文字反馈 RL 在 pilot 中的答对题数高于冻结 writer，`full` 读取相同 checkpoint，在训练之外的患者 3、4 上按时间顺序遍历 3,541 个来源块，评估全部 189 道题。最终比较使用仓库已有的同题 RAW-RAG 评分。pilot 点估计用于决定是否进入完整实验，重复种子稳定性需要另外测量。

```bash
../MedMemoryBench/.venv/bin/python experiments/qwen27b_rsi/run_targeted_writer.py full --out results/targeted_writer_run
```
